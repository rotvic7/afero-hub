H Hunter Hub · operação local ← voltar ao catálogo
guia operacional · v1

Da oferta caçada ao funil pronto no computador.

Este documento define como o Hunter Hub organiza uma oferta de alto potencial, transforma suas decisões em arquivos de projeto e entrega o contexto certo para o Codex ou o Claude Code executarem a Copy e a Página.

local-first 3 agentes aprovação por etapa checkout em aberto
01 · escopo

O que vive no Hunter Hub

O Hub funciona como cockpit do projeto. Ele registra a oferta, coleta a direção e organiza os arquivos. A execução criativa acontece no computador do usuário.

Caçador de Ofertas

Pesquisa, classifica e registra a oferta escolhida, com evidências da página e dos sinais capturados.

Agente de Copy

Recebe o briefing exportado e escreve a mensagem de venda para revisão antes da Página.

Agente de Páginas

Transforma a copy aprovada em HTML, preserva o vídeo autorizado e mantém os links de checkout vazios.

Fora da primeira versão

Entregáveis, Quiz, backend remoto, cobrança, publicação automática e execução direta de comandos pelo navegador.

02 · sequência

O funil em cinco movimentos

Cada passagem gera um arquivo e uma decisão clara. O próximo agente só recebe o material depois da revisão da etapa anterior.

01
Caçador de Ofertas entrada

O usuário escolhe uma oferta do catálogo ou informa uma URL. O Hub congela o diagnóstico e as evidências para o projeto.

oferta-original.md · diagnostico.json
02
Direcionamento no Hub decisão

O formulário reúne produto, público, promessa, ângulo, tom, vídeo, referências e regras de checkout.

briefing.md · projeto.json
03
Agente de Copy Codex ou Claude Code

O agente lê o briefing e as instruções versionadas, cria a copy e salva uma versão para aprovação humana.

resultados/copy/copy-v1.md
04
Revisão da Copy gate humano

O usuário aprova, pede ajustes ou gera uma nova versão. A Página só começa com uma copy aprovada.

copy-aprovada.json
05
Agente de Páginas saída

O agente monta o HTML, valida a navegação e salva o preview local para conferência no navegador.

resultados/pagina/index.html
03 · formulário

Como o projeto é preenchido no Hub

A tela separa fatos detectados pelo Caçador das decisões que só o dono do projeto pode tomar.

preenchido automaticamente

Contexto da oferta

URL, título, score, gateway, rastreador, screenshots, copy capturada, vídeo e data da captura.

preenchido pelo usuário

Direção estratégica

Produto, público, problema, promessa, ângulo original ou adaptado, faixa de preço e objetivo da página.

preenchido pelo usuário

Direção da mensagem

Tom, mecanismo, benefícios, objeções, garantia, CTA e seções obrigatórias.

regra de ativos

Vídeo e checkout

Vídeo preservado quando autorizado. Checkout principal e secundário ficam vazios até serem criados.

Antes de exportar: o Hub mostra um resumo do projeto. O usuário confirma a direção e só então a pasta local é criada.

04 · exportação

O que sai do Hub para o computador

O launcher local abre o painel em localhost, grava os arquivos em hunter-hub/projetos/ e prepara os dois adaptadores de ferramenta.

Codex · abrir projeto
Leia AGENTS.md e execute apenas a próxima etapa autorizada.
cd "...\projetos\corpo-conectado"
Claude Code · abrir projeto
Leia CLAUDE.md e execute apenas a próxima etapa autorizada.
cd "...\projetos\corpo-conectado"

O mesmo processo, duas ferramentas: AGENTS.md e CLAUDE.md apontam para as mesmas regras centrais. O Hub não coloca chave de API no navegador e não publica o resultado.

05 · contratos

Arquivos que mantêm o trabalho alinhado

Cada arquivo tem uma função curta. Isso mantém o contexto verificável quando o projeto troca de agente ou de ferramenta.

projeto.json

Estado, slug, etapa atual, aprovações, referências e caminhos dos artefatos.

briefing.md

Decisões humanas preenchidas no Hub, em linguagem legível para revisão.

AGENTS.md

Adaptador de instruções para o Codex seguir o processo local.

CLAUDE.md

Adaptador equivalente para o Claude Code, sem mudar o conteúdo do fluxo.

07 · controle

Estados e travas do projeto

O arquivo de estado impede que o agente pule uma aprovação ou sobrescreva uma versão sem histórico.

oferta-selecionada aguardando-direcao copy-em-revisao copy-aprovada pagina-em-execucao pagina-em-revisao pronto-para-exportar

Regra de aprovação: Copy aprovada libera Página. Página validada libera a exportação final. O deploy continua sendo uma decisão posterior do usuário.

08 · antes de rodar

Checklist rápido

Use esta conferência sempre que iniciar uma nova remodelação.

  • Oferta escolhida e evidências salvas no projeto.
  • Promessa, público e ângulo definidos no formulário.
  • Direito de uso do vídeo e das referências confirmado.
  • Links de checkout mantidos vazios até a criação.
  • Copy revisada antes de chamar o Agente de Páginas.
  • Preview aberto em navegador real antes de qualquer publicação.
